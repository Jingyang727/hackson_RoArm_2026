# RSI第一版：完整抓放、录像、定性复核、下一轮参数

分支：`feature/rsi-pick-place-loop-v1`，从main的`checkpoint-xyz-control-v1`起步。原有坐标页、标定、官方复位和单串口所有者继续使用；“抓取试验”页成为完整抓放入口。旧`grasp_once`CLI仍保留旧的抓取提升语义，本版请使用新页面或`/api/bench/rsi`。

目标是在可执行工作区内，定位桌面任意位置的34mm黄球，夹起并放入可移动黑漏斗（内径76mm、高45.4mm）。第一版运行一次完整尝试，保存结果，再由人工或本地公司Grok复核并更新下一轮参数。尚未接入无需复核的无人值守循环，不宣称一次成功就完成全工作区验收。

```text
不要调用旧grasp_once/bench_start，也不要替我发送运动、复位或扭矩切换。
由我在 /experiments 页面启动第一次完整抓放。
```

启动方式与原服务相同：

```bash
EVOARM_ENABLE_TEACH=1 EVOARM_ENABLE_MOTION=1 EVOARM_SETUP_ID=bench-layout-v2 \
/Users/jyang51/miniconda3/envs/evoarm/bin/python -m uvicorn control_ui.main:app --host 127.0.0.1 --port 8765
```

相机、底座和桌面默认固定；继续使用五点标定，棋盘可撤走。球和漏斗应同时完整可见，初始球在桌面上、夹爪中没有物体。漏斗内部可见便于视频复核；不要求另配Grok HTTP网关。

1. 打开 `http://127.0.0.1:8765/experiments`。点击“观察并规划抓放”，采集2秒当前RGB-D，不移动机械臂。
2. 核对画面里的球、漏斗及完整路径。页面显示球心XYZ、实际深度拟合是否使用、样本数、漏斗口XYZ、速度与参数版本；可展开深度图。识别/规划失败也保留本次观察图，不复用上一次已准备计划。
3. 确认整臂空间后勾选，点击“执行一次抓放并录像”。开始本次带请求ID的10秒RGB-D录像，再按计划张爪、到球上方、下降、合抓、提升、运输到漏斗上方、松爪。需要时先抬升或增加通过检查的过渡点，不使用示教任务位置。
4. 页面显示实时预览；结束后可播放视频、看关键帧。闭爪、投放动作是否发出，实际耗时、录像覆盖和视觉结果分别记录。状态到位不自动标记抓住或进入漏斗。
5. 在下方选择实际结果和可见方向，保存复核。程序只更新下一轮参数，不发送运动。点击“重新观察下一轮”后，用新图、新目标、新参数再做一次。

第一轮先验证完整动作与感知。之后移动黄球、漏斗覆盖多个可达位置，记录成功率和耗时；单点修正不能替代全区验证。

## RGB-D与指尖坐标

黄色区域来自RGB，球面有效深度经本帧内参和已保存变换进入机械臂坐标系，再拟合已知半径17mm的球面。平面高度为弱先验，不用桌面深度冒充球表面。深度不足或拟合不可靠时明确退回桌面+球径估计并给出警告；存在可靠而明显矛盾的深度证据时保留原有拒绝与画面。

黑色近圆形开口按外观、尺寸和形状筛选，多个接近候选会提示核对。漏斗口XYZ由当前RGB中心、已测45.4mm高度和桌面平面计算，轮缘有效深度留作诊断；洞内桌面深度不作为开口高度。

固件XYZ是固定指尖，不是夹持中心。第一轮使用19mm的实验性指尖到球心偏移，抓取高度偏移+3mm、张爪110°、闭爪目标上限3.14rad，抓取时优先尝试80°附近的向下俯仰。完整路径均经过现有IK、官方关节范围与桌面检查。稳定停在闭爪目标之前时只视为“接触候选”，由执行线程另发一次实测角度保持，再尝试提升；不以此宣称已抓住。

可能失败的地方包括：相机/标定残差、指尖与夹持中心偏移、肩部受载偏差、手指推走球、闭爪后的滑落、漏斗投偏与弹出。先记录真实发生的阶段，再调整参数；不要求Grok凭视频给出准确毫米值。

## 速度与10秒目标

| 动作 | 初始参数 | 接口含义 |
|---|---|---|
| 运输、提升、球上方接近 | T104 spd=0.65 | 固件笛卡尔插值速度参数，不是mm/s；不附加无效acc字段 |
| 最后下降 | T104 spd=0.30 | 接近阶段单独配置 |
| 张爪、闭爪、释放、接触保持 | T106 spd=1000、acc=20 | 速度为舵机步/秒，加速度沿固件夹爪接口定义 |

普通手动控制保留原0.8秒最小指令间隔；本轮独占、前一段已确认的RSI步骤使用120ms的最小衔接间隔。动作仍串行，仍逐段检查反馈，未确认的动作不能跨过。

复用坐标页的XYZ反馈分类，不为省时要求每个夹爪/姿态误差都精确归零。10秒是实测目标而非成功保证。录像开始后9.6秒不再发送新的步骤，超窗、相机结束、串口错误或动作未确认时停止后续指令，记录本轮未完成。已经被固件接受的运动可能继续，软件停止不是硬件急停。

## RSI如何调整

| 定性结果 | 下一轮操作 |
|---|---|
| 夹爪在画面里偏左/右/上/下 | 用相机到机械臂变换计算4mm修正，分别作用于抓取或投放XY |
| 抓取位置太高/太低 | 抓取高度下降/上升2mm |
| 下降时推走了球 | 先提高抓取高度2mm，下一轮验证这一假设 |
| 提升或运输中滑落 | 快速移动速度降低15% |
| 投放太高/太低或弹出 | 投放高度小步调整4mm，保留漏斗口上方间隙 |
| 抓起并进入漏斗 | 保留参数，换位置验证 |
| 看不清、方向不明、控制/录像故障 | 记录证据，不凭空修改抓取参数；故障需复核后再试 |

一次只更新对应的一组参数。XY学习偏移限制在±30mm、抓取高度修正−10～+15mm、释放净空5～45mm；这些是学习搜索域，不是机械臂工作区或关节范围。角度始终沿用官方范围。每个试次ID只能应用一次反馈，重发不会累计修正；参数原值、新值、位置、来源和版本都保留。新标定指纹使用独立策略文件，旧坐标系的偏移不自动带入。

第一版是用反馈更新确定性策略参数，并非在线训练模型权重。历史定性反馈会显式进入下一次Grok复核上下文；未来接Langfuse也要主动检索，不能假定日志自动被模型读取。

## 本地Grok复核

点击“生成Grok复核资料”，把页面文本交给本地OpenCode/Grok。它读取本次MP4和关键帧，只提交定性结果，不输出毫米修正或电机命令。也可直接：

```text
GET http://127.0.0.1:8765/api/bench/rsi/context/<plan_id>
读取 video_path、keyframes_path、instructions 和最近历史。
按 review_template 填写定性结果，POST到 /api/bench/rsi/review。
source填写company_grok；遮挡或证据不足用unknown。
第一轮完成后回传结果与参数变化，不自动启动下一轮。
```

示例反馈：

```json
{"plan_id":"<32位本轮ID>","outcome":"grasp_missed","direction":"image_left","source":"company_grok","note":"夹爪在原始RGB画面中偏左，球未离桌"}
```

方向以本页未镜像RGB为准，与坐标页左右镜像无关。Grok不直接填写速度、毫米数、关节角或命令；额外控制字段被接口拒绝。它若要宣称入漏斗，必须有本轮投放且录像完整，不能只依据T1051或HTTP成功。

## 接口和数据

`/api/bench/rsi`包含`GET /state`、`POST /prepare`、`POST /run`、`POST /stop`、`POST /review`、`GET /context/<id>`和`GET /history`。run载荷为plan_id与声明“已核对黄球、漏斗和完整抓放路径，现场有人看护且双手离开运动范围”。每次prepare纯只读，计划180秒有效且仅在当前服务中可执行；服务重启不会恢复执行，但已完成试次的上下文、媒体与复核可从磁盘读取。

运行保留独占pending标记，覆盖录像启动、每段确认之间及保存录像期间，其他运动入口不能插入。状态GET只读，接触保持只在已授权的执行线程中发送。每次写入前记录消耗的指令，不确定写入不重试；停止或异常后撤销授权，不自动复位或切扭矩。

本地文件：

- `~/.evoarm/rsi/pick_place_runs/<plan_id>/`：预览、深度图、状态、attempt.json及各段坐标反馈。
- `~/.evoarm/rsi/experiments/<capture_trial_id>/`：10秒RGB、深度、帧时间戳、关键帧、rsi-plan.json及rsi-trial.json。
- `~/.evoarm/rsi/pick_place_policies/<setup_id>/<calibration_fingerprint>.json`：版本化参数及已应用反馈。

这些本地实物数据不提交到仓库。完整模拟设备测试和页面测试不能代替现场首轮验收；首次结果用于确定真实的误差来源。
