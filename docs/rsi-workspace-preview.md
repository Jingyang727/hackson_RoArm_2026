# 当前策略的可抓取区域与规划阶段诊断

基线是 main `e3eaf65`，文件内容对应实机正在运行的 `1fb707b`。本次从 main 新建 `feature/rsi-reachability-map`，不引入另一个分支的单边开爪偏置或视觉阶段协议变更。漏斗大开口定位、球心/指尖换算、投放XY补偿和口沿间隙沿用当前版本。

## 为什么回到初始姿态仍可能无法规划

官方初始姿态是起步状态，不会让任意球位置都产生可执行路径。相机可见的位置，还需要同时满足抓取俯仰、下探、抓后抬升、运输和漏斗投放姿态。完整路径搜索失败也不等于整个机械臂永远无法到达该位置；不同策略可能产生不同区域。

本次发现一个独立的高度耦合问题：旧规划器用所有候选投放姿态的最高端点计算统一运输高度，即使该高端点候选最终没有被选中。现在各投放候选只使用自己的端点高度加10mm过渡间隙，并保留经验抬升高度和障碍通行高度。旧版回放例中，不必要的统一高度约172mm；按最终选中的30°投放姿态，约156mm即可通过同样的路径检查。

修正不改变官方关节范围或检查规则。抓放路径仍先抬升、高处转移、竖直下探；新路线版本是6。未使用的更高候选不再抬高已经可用的路径，相关回归测试比较了加入该候选前后的完整指令序列。

## 网页操作

在 `/experiments` 勾选 **显示当前可抓取区域（不运动）**：

1. 用现有相机服务采集当前球与漏斗，读取一次当前机械臂姿态。
2. 在相机视野内的桌面上，以34mm球的球心高度17mm采样32×18个位置。每个绿色位置都用当前策略、实际起步姿态和漏斗位置调用完整抓放规划器。
3. 绿色表示该采样点找到完整候选路径；灰色表示本轮候选搜索未通过；空白表示未完成采样。数学计算预算12秒，采集时间另计。预算耗尽不能把未计算位置涂成不可达。
4. 页面另外核对本次观察的实际球心，显示抓取姿态、运输高度，或失败阶段及建议。边界是采样估计；绿色不能保证夹取成功率或中间所有位置都可执行，实际执行仍逐段读取反馈并检查路径。

该图只作为摆球参考，不新增运动门槛，不限制用户在坐标验证页选点，也不改变经验参数。区域会随起步姿态、抓取/抬升高度、俯仰、漏斗位置和当前策略变化。改变条件后点击“重新计算区域”；新计划使用不同起步姿态、漏斗位置、参数或相机几何时，页面隐藏旧图，避免把旧区域当成新条件的结果。

该功能不调用视觉大模型，不解锁、切换扭矩、回位或下发运动。数学计算在独立线程运行，控制器锁仅用于读取起步状态。缓存仅属于这一次冻结的计算输入，不参与实际运动检查。

## 起步检查、回位与规划失败

- 先显示“核对起步姿态”；确实需要T100时才显示“恢复官方姿态”。已在官方初始姿态且反馈稳定时，保留原有免回位分支。
- 若几何规划失败且已确认在官方初始姿态，本轮直接显示失败阶段，不再重复相机采集和同一次路径搜索。不修改策略或自动尝试其他球位置。
- 若确实从其他姿态回位，保留回位后的一次重新定位与重规划。回位失败的原因单独显示，不与抓放路径失败混为一谈。
- 页面显示搜索推进到的最深失败段、该段原始原因和目标/俯仰/关节等证据。高处运输或投放失败时会提示检查漏斗或通道，而不是一律要求移动球。

完整失败备份继续保留 `planning-input.json`、`calibration-snapshot.json`、`prepare-error.json`、现场图像；新增 `planning-diagnosis.json`。学习任务的 `state.json` 也保存 `planning_diagnosis`，无需再次手工找控制台日志。

## 接口与本地记录

- `POST /api/bench/rsi/observe`：沿用已有只观察接口。
- `POST /api/bench/rsi/workspace`，正文为 `{"observation_id":"<32位ID>"}`：验证活动标定，冻结当前姿态与策略，启动纯数学预览。只读运行模式也可用。
- `GET /api/bench/rsi/workspace/<workspace_id>`：读取进度和结果。网格字符 `+` / `-` / `?` 对应绿色、灰色和空白。
- 本机记录：`~/.evoarm/rsi/workspace_previews/<workspace_id>/input.json` 和 `state.json`。预览不写入活动标定或策略；必要的旧策略兼容转换仅在内存中供本次计算使用。

`/api/bench/rsi/state` 新增 `workspace_preview_version=1`；保留 `api_version=10`、`web_learning_version=3`、`visual_pipeline_version=3`。沿用本机Python、相机服务、模型配置和活动数据，从新分支目录重启网页服务后刷新页面。服务继续仅监听 `127.0.0.1`，本次只验收桌面浏览器。

离线验证使用模拟设备、规划器回归测试及用户提供的既有RGB-D数据；不会触发真实机械臂。由于本次没有保留用户所述失败现场日志，不能断定该次失败就是高度耦合问题；新诊断用于保存下一次的具体依据。

本分支也包含[坐标页速度与途径点等待](coordinate-validation.md)：默认速度0.65，提供1.0快速选项，取消分段已停稳后的固定8秒等待。

自动抓放也可在网页[分别配置转移／抬升和下探／靠近速度](rsi-speed-settings.md)。保存速度后，已有区域预览失效，下一轮使用新参数重新规划。

已通过574项Python测试、18项Node测试与桌面Chromium验收。用户既有场景的576点完整回放耗时约6.3秒，其中251点找到候选路径；这些是模型计算结果，不是实物抓取统计。浏览器验收确认了区域显隐、场景叠加、失败阶段展示及没有自动发送抓放/扭矩/复位/授权请求。
