# RSI v10：让执行失败也进入学习闭环

本版针对上传的三轮OpenCode日志：68c1e60c、db6613ee、be5146deb5。三轮参数均未改变，也没有动作后的视觉结论或decision。前两轮到抬升已约9.5秒，第三轮在运输开始时因实测间隙不足被拒绝。它们是执行问题，不能靠重复相同路径或猜XY补偿解决。

接口版本10，路径版本4。保留当前活动标定、原Gemini Python、相机服务、公司模型登录、10秒录像/动作预算和原有几何检查。

## 读图权限的实际错误

OpenCode 1.19.0的read工具按 `path.relative(instance.worktree, filepath)` 检查权限；旧规则只写 `**/.evoarm-agent-evidence/**/*.jpg`，不匹配项目根目录下以 `.evoarm-agent-evidence/` 开头的相对路径。现在同时放行这个相对路径，仍拒绝其他文件。

用官方1.19.0二进制实际执行debug read验证：旧规则拒绝、新规则成功返回图像附件、证据目录外文件仍拒绝。只验证读图，不调用公司模型、不移动机械臂。子Agent访问失败时立即报告一次，主Agent不得把未看图的ready=false自行替换为ready=true，也不在操作任务中搜索代码或配置修权限。

## 清晰的工具输入输出

`state`、`wait`、`context`、`readiness`默认输出有界摘要，完整数据用 `--full`。摘要区分当前job、learning、pending与历史result；等待返回 `task_finished`、`waiting_for`，不会把旧lift反馈当成机械臂还在执行。软件任务结束不证明实物静止，恢复前仍使用原有新鲜稳定反馈检查。

支持 `wait --seconds 30`、兼容 `--timeout 30`；context允许直接传32位ID，也容忍日志中的PLAN_ID=前缀。每次只调用一个命令，不拼接多段JSON使输出再次截断。result和memory笔记不再整段淹没当前控制状态。

新增只读命令：

```text
python -m evoarm_rsi.agent_tools diagnosis <本轮ID>
```

读取已存收据、返回阶段开始/完成秒数、执行分类、lift目标与末次反馈XYZ、相对标定桌面的高度。旧轮次也可诊断，不会重放。context列出当前标定最近3轮执行事实，让主Agent知道之前改了什么、哪里重复失败。

72.4mm是相对桌面的间隙，不能与机器人Z=-19.6mm直接相减；44.041mm是三维到位误差，不能直接当作竖直欠升。高度试验建议只从实际XYZ与桌面平面计算，没有反馈时不猜绝对补偿。

## 减少冗余路径，保留低位起步抬升

起点已经足够高时，优先在通过完整检查的高处区域内，将横向接近、下降到预抓高度、转腕与张爪合并一段，再竖直下探。低位起步仍先沿原XY抬升，整个横移段仍检查桌面、连杆、IK和关节范围。合并候选不通过时才回退原分段候选。

夹住后沿实际反馈XY竖直抬升，同时逐渐切换到选定的运输姿态，避免一直保持伸展的80°抓取姿态到抬升后再转腕。投放指尖仍随最终姿态重算，漏斗上方停稳后释放。

上传布局的几何回归能减少一个冗余对齐段；不把模拟设备的耗时当作真机10秒证明。窗口不延长，间隙与反馈检查不放宽。

## 执行与视觉分别学习

每轮：readiness/context → prepare → scene视觉复核 → run/wait → diagnosis → 执行失败时先恢复 → 原录像result视觉复核 → decision → remember → 有效新决策后再准备下一轮。

Grok仍只给定性结果。主Agent根据确定的执行证据，可以在decision的parameter_trial中选择：

- time_budget：单独试验travel_speed或approach_speed。
- clearance_shortfall：按真实目标/反馈高度差试验lift_height_mm。
- 抓取/投放的可见偏差：沿用XY、夹持高度、指尖偏移、预紧等视觉试验。

执行参数不要求Grok测量绝对误差；它们依据机器人反馈与时序，不伪装成视觉估计。仍只改一个参数，保存前通过完整参数边界和路径IK；调参只是试验，不预称已提高成功率。执行故障不接受XY试验步长。

执行Agent必须提交本轮绑定的scene复核才能运行；未复核上一轮结果时，下一次prepare拒绝。对于同一标定、相近物体位置、相同路径版本下的超时/抬升不足，未改变参数就不原样重试。旧路径升级到v4可以先验证新流程，不把路径升级的效果归因于单项补偿。网页直接API循环保持原入口，不与OpenCode同时启动。

## 本机验收

更新运行中的worktree并重启普通网页服务，确认API版本10，保持原标定和独立相机服务。在同目录重开OpenCode，先 `/roarm-rsi` 只读核对。先对已有失败轮次运行diagnosis，使用vision让子Agent实际读取原录像，再保存decision；补历史复核不重放历史动作或已完成复位。

现场准备好后，建议先请求 `/roarm-rsi go，最多1轮` 验收新路径和实际时序。明确指定轮数时不自动补足默认3轮。只有run返回started=true才计一次实物尝试；计划过期和读图失败不计。新一轮若失败，也必须先解释执行证据与有效参数变化，再进入下一轮。

每轮原视频、RGB-D、指令、反馈、执行诊断、视觉结论、策略变化和Langfuse待同步记录继续保存。真实图像无法判断时保留unknown；本版没有用推测的XY补偿替代缺失画面。
