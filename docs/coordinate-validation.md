# 先验证 XYZ，再接球定位

相机、机械臂底座和桌面默认固定，直到用户明确报告发生移动。已完成的五点标定继续使用，物理棋盘可以撤走；移动棋盘、球或漏斗不会改变保存的相机到机械臂变换。此页不要求相机在线，也不调用Grok或抓取流程。

## 点位验证

1. 未连接时点击“连接机械臂”，现场看护串口初始化。若之前有锁存故障，先核对实物已经静止，再点击“确认机械臂静止并复核异常”；沿用原有只读稳定反馈复核，不发送运动、不切扭矩。
2. 默认使用“图上选点”：在三维图或XY俯视图中点桌面网格选位置，再拖动“目标离桌高度”滑块确定Z。XYZ自动生成，桌面落点到目标的竖线表示高度；点图、改高度和拖动视角均不发送运动。XZ侧视无法唯一确定桌面位置，需切回三维或俯视选XY；仍可用滑块调高度。
3. 默认“自动选择可达俯仰”：优先保持当前俯仰，若不能通过检查，再按与当前角度的距离顺序检查5°网格候选。候选角范围从官方肩、肘、腕角度范围推导，不额外限制在±90°。这只是纯计算，不会让机械臂逐个尝试；也可明确选择“保持当前俯仰”。点击“预览目标和路径”，灰色骨架显示目标姿态，文字显示俯仰起点→终点，橙点与虚线显示XYZ直线路径。改选点、高度或俯仰模式都会清除旧预览和勾选。显示网格不截断可选XY，也不代表可达边界。图由原装夹爪连杆模型和真实反馈绘制，不是外部相机测量。
4. 核对实际整臂运动范围和预览姿态后，勾选现场确认，点击“移动到这个点”。只发送一次官方 `T104`，使用预览确定的俯仰，保持当前末端旋转，夹爪使用当前开度对应的合法保持目标；执行时不重新搜索、不重试、不回到示教位置。
5. 对照输入目标、固件反馈和X/Y/Z各轴差值，检查实物末端是否落在期望位置。填写“基本一致／有偏差／尚未确认”及备注。控制器数字到位与人的实物验收分别记录。

坐标单位是mm，使用固件机械臂基坐标系：X为正前方，Y为水平侧向，Z向上；O是固件原点，**Z=0不是桌面**。页面会同时显示末端和目标离已标定桌面的高度。固件XYZ指默认工具的名义指尖，不等于张开夹爪的夹持中心。

已取消固定25mm离桌门槛。高度滑块从保存平面0mm开始；0–25mm范围只显示近桌面提示，不禁止预览或执行。目标不得低于保存平面，仍沿实际T104路径检查逆运动学、官方接口角度范围和连杆离桌高度，速度保持0.12。若当前反馈已经低于保存平面，仅允许保持XY竖直向上离开，不继续向下或横穿桌面。平面高度是标定模型，接近0mm可能实际接触桌面，三维示意图不替代实物间隙检查。

## 已清理的限制与保留条件

统一范围来源是[官方文档](https://www.waveshare.net/wiki/RoArm-M3)及[20260701参考源码](https://www.waveshare.net/w/upload/4/48/RoArm-M3_example_20260701.zip)。`evoarm/limits.py`为唯一数值定义；坐标、抓取路径、旧关节API和health共用，不再保留另一套手动训练范围。

| 关节 | 已删除的训练范围 | 当前官方名义范围 |
|---|---|---|
| 底座 | ±75° | ±180° |
| 肩 | ±50° | ±90° |
| 肘 | 35°～145° | 0°～180° |
| 腕俯仰 | ±60° | ±90° |
| 旋转 | ±90° | ±180° |
| 夹爪 | 65°～180° | 1.08～3.14rad（度数上界显示名义180°） |

肘舵机参考源码的计数上界对应约179.91°，表格180°是名义值；夹爪保持及T106仍明确限制在3.14rad。网页展开“关节范围与路径检查”可查看后端实际范围。API版本4；页面与旧后端混用会明确提示重启，避免静态文件已更新但服务仍运行旧检查。

已删除图上选点的X/Y网格硬截断和额外±1000mm输入边界；有限坐标通过真实连杆几何判断。已停用由旧±60°范围产生的“先收腕到55°”流程，旧`start-once`接口明确返回停用且不读写设备。

保留的检查包括：有效五点标定；固件XYZ与原装工具FK一致；目标与指尖路径不低于保存桌面；上游连杆端点离桌至少30mm（项目间隙，不冒充厂家限制）；全路径IK、官方关节范围及底座角度分支连续性；执行时新鲜六关节锁定、无pending/fault、位姿未漂移、现场确认和单次发送。范围不是防碰撞模型，夹爪、桌面物体及整臂实际扫掠仍由现场核对。

拒绝信息包含目标或路径进度、XYZ、俯仰，以及所需关节角度/允许范围或几何无解原因；自动搜索失败时保留各候选原因。自动模式只是有限候选的直线规划，不代表穷尽所有绕行路径。

## 扭矩与按钮判定

“扭矩锁定”是舵机有保持力，`torswitch=1`或`true`；`0`或`false`显示为“上报0”，字段缺失或其他值标为“未知”。参考官方20260701源码中，读取某舵机反馈失败也会将它的Torquestatus置0，因此仅凭T1051的0不能唯一判定物理扭矩已释放。页面不会把它说成“用户没有锁好”；真实发送前仍需要六项为1/true。运动授权是另一层软件权限：点击移动申请授权，动作结束撤销授权，不会释放扭矩。

纯预览只计算路径，不发送运动，也不要求锁定扭矩或开启实物执行模式。实际发送T104前仍读取新鲜状态，确认六关节全锁定、无故障、无待完成运动并经过现有预检。未确认锁定时只禁止执行，不会自动发送扭矩切换命令。

页面显示本次T1051中的六关节实际状态，可展开查看每个字段原始值和health缓存数组。每个灰按钮下方显示其禁用原因：例如尚未预览、未勾选现场确认、只读模式、反馈缺失、某个关节上报0/未知、故障或动作进行中。旧前端只接受数字1，导致布尔值true被误判；现与后端规则统一。物理感觉锁定与程序实际读到的状态若有出入，应查看原始反馈，不能据提示盲目切换扭矩。

## 闭合夹爪的反馈与保持目标

用户没有输入夹爪角度。设备在180°闭合位置可能上报180.8°等略超边界的反馈，原始反馈必须保留，不应直接把它作为超限的新指令发送，也不应因此拒绝XYZ验证。

XYZ验证保留夹爪±2°反馈容差与向合法范围恢复规则：正常范围内保持原值；略超范围时，T104使用合法边界的保持目标。固件上界3.14rad约为179.9°，因此180.8°反馈对应179.9°保持指令，预览同时显示两个数。没有额外T106开合或复位指令，不增加闭合目标；并不保证夹爪实际角度完全无变化。反馈超过容差仍拒绝，并在执行前重新读取检查。

## 反馈与记录

反馈在位置参考带内稳定后显示“进入6mm参考带”；夹爪、旋转和俯仰的差值显示出来，**不会再作为XYZ到位的额外门槛**。位置已经停稳但有偏差时显示实际差值，结束这次验证并撤销授权，不悄悄重试，也不宣布实物准确。超时、缺失反馈、扭矩变化和传输不确定保持故障处理；刷新不会重发。已经在目标附近时明确显示未发送运动。

每次预览/移动独立保存到 `~/.evoarm/rsi/coordinate_runs/<plan_id>/report.json`，包含目标、T104载荷、原始反馈、逐轴误差、姿态差和独立的实物验收。改输入会使旧预览失效；执行前核对起始姿态和标定，执行计划只能消耗一次。

## 实测深度查看

页面下方“查看已采集的RGB-D与空间点”读取已有实验录像，明确标记**非实时**、录像ID和帧号。RGB与深度是同一配对帧；深度伪彩图用毫米尺度显示，黑色表示空洞。

点击RGB或深度图中的像素，使用实际采样的深度：

```
p_camera = depth_mm × inverse(K) × [u, v, 1]
p_robot  = R_camera_to_robot × p_camera + t_camera_to_robot
```

页面显示这个像素的相机XYZ与机械臂XYZ，并在三维视图中标出表面点。深度缺失时不输出空间点；不从桌面模型补值，不触发运动，也不会把表面点说成球心。

此前抓取入口主要用保存平面与34mm球径估计目标，深度用于一致性检查。自动球心定位尚未接入：点位运动验证通过后，再从黄色球区域的有效三维表面点结合实测直径估计球心，将人工输入XYZ替换为该目标。
