# RoArm肩部偏差与小角度不响应：资料核对

核对日期：2026-11-11。以下是公开资料与下载源码的结论，不等于已经诊断了用户这台设备。

## 已确认的公开依据

1. [官方FAQ](https://docs.waveshare.net/RoArm-M3/FAQ/)专门说明了“JSON控制某关节无明显动作”的排查次序：先比较自带Web角度控制与JSON控制，再检查命令、线缆/机械限制和供电连接。FAQ同时指出肩部是双舵机，中位不一致可能堵转。
2. [官方资料页](https://www.waveshare.net/wiki/RoArm-M3)提到过低速度可能在特定位置引起抖动；金属外壳Pro与塑胶外壳S的虚位表现也有差异。这不足以单独解释某次完全不动作。
3. [第三方公开肩部负载讨论](https://github.com/metrox-eth/moss/issues/2)对比了RoArm的双肩舵机、负载和控制参数。这个issue讨论的主体是另一台原型机械臂，不能当作“RoArm已知相同故障”的确认。

没有查到可据以确认“RoArm固件统一忽略1°/2°命令”的官方issue。

## 官方下载源码中的事实

来源：[RoArm-M3_example_20260701.zip](https://www.waveshare.net/w/upload/4/48/RoArm-M3_example_20260701.zip)

本次下载文件SHA-256：`a28247fee0bbb65cc034ff206031b8700d2b1ec8e3a1fa4b1a5a7365c55f1a57`。

- `RoArm-M3_module.h` 的 `calculatePosByDeg` 按4096步/360°转换并四舍五入。1°约11.4步，因此“磁编码器分辨率不足以表示1°”不能单独解释现象。
- `RoArmM3_shoulderJointCtrlRad` 给两个肩舵机发送互为镜像的目标。
- `RoArmM3_moveInit` 包含肩部从动舵机释放、主动舵机回中、等待、重设从动中位、恢复保持力的过程。版本和零位状态对肩部很重要；这不是建议现在执行初始化。
- `RoArmM3_resetPID` 在这份源码里使用P=16、I=0；`tS`由两肩舵机负载相减得到。单个`tS`不能揭示两侧分别承担多少负载。

源码的控制设置使“受负载时有稳态偏差”成为应调查的可能原因，但当前证据不足以判定重力、静摩擦、虚位、扭矩限制、双舵机配合或供电哪个是主因。用户设备可能运行不同固件。

## 下一步实际需要的证据

先执行无运动的 `task_agent doctor`，取得当前状态、三次反馈、真实目标记录、已有标定和相机信息；同时确认S/Pro型号、是否改过固件/舵机设置。

之后再设计一次经现场确认的、有限幅度的对比实验，记录同一姿态下向上/向下响应及保持时漂移。幅度与姿态根据实际状态选择，不预先要求追逐1°微动。已有 `control_calibration` 可以提供数据格式，但不应未检查场景就直接运行默认J1/J2/J3批次。

本次不自动调整PID、扭矩、零位或扩大到位容差。先分清“请求已接收”“确有运动”“停稳有残差”和“任务成功”四种事实。
