# EvoArm P1 · 棋盘格毫米坐标与黄色球识别

## 当前目标

**只做像素 → 桌面棋盘坐标的二维变换**。这一阶段绝不会调用 RoArm-M3 的串口运动接口，也不把图像传给外部服务。用户手动检查拍摄结果后才能继续下一阶段。

用户提供的图像已成功检出 54 个角点（9列×6行内部角点），并检测到黄色球（像素约 549,1027）。黄色球位于棋盘格内部角点区域之外，当前毫米定位是**外推结果，不可直接用于抓取**。

### 建立棋盘格坐标系

- 棋盘格有 **10列×7行方格**，**9列×6行内部角点**。
- **O=(0,0)** = 棋盘格左上角的第一个**内部角点**，不是纸张的边缘。
- **+X** = 顺棋盘格向右（横向）；**+Y** = 顺棋盘格向下（纵向）。
- 单位设为 **mm**。实测一个方格的边长 `L` mm，最右下内部角点为 **(8L,5L)**。
- 实测方法：连续测5格长度，再除以5；不假设 A4/打印缩放正确。
- 棋盘纸和摄像头保持不动。改变任意一方姿态后，需要**重新采集和标定**。
- **Z=0** 定义为桌面棋盘平面；目前未测量球体高度、夹爪末端到桌面的高度。

### 在 Mac 上使用

```bash
git fetch origin
git switch --track origin/feature/evoarm-vision-calibration-p1
source .venv/bin/activate
pip install -r requirements-vision.txt
python -m unittest discover -s tests -v
python -m uvicorn control_ui.main:app --host 127.0.0.1 --port 8765
```

打开 http://127.0.0.1:8765/camera ：
1. 摄像头预览采用 1920×1080（若摄像头不支持则回退）。
2. 量好单格长度后，在输入框填写 mm；不填写只能输出棋盘格单位。
3. 点击「检测棋盘格和黄色球」；程序截取当前一帧 PNG 上传到**本机**的 FastAPI 服务。
4. 页面画出棋盘格54角点和黄色球边框/中心，显示 `board_mm_xy`、是否在棋盘格角点范围内，以及警告信息。
5. 若小球位于棋盘格范围外，先验证已知位置误差，不要直接用于机械臂 XYZ 控制。

### 注意：二维毫米不等于机械臂坐标

上面坐标是 **棋盘格参考坐标**，不是 RoArm-M3 底座坐标。接下来还需要：

1. **相机到机器人 XY 对齐**：从几个在安全工作空间内、分布开且不共线的物理定位点，记录棋盘平面(mm)和机器人实际反馈的 X/Y(mm)，拟合变换并独立验收测试点。
2. **Z 高度校准**：棋盘桌面高度、工具中心偏置、黄色球实际半径和夹爪抓取高度分别测量。黄色球是离开棋盘平面的三维球面，图像上的彩色区域中心不一定等于球心的桌面投影。
3. **镜头畸变校准**：现阶段一张图只能拟合平面单应，不能完成严谨的多视角相机内参/畸变标定。若工作区远离棋盘格范围或误差大，需要补拍多个不同姿态的棋盘格图、计算内参并矫正畸变。
4. **机械臂运动约束**：即使得到正确 XYZ，自动抓取也需要工具姿态、夹爪距离、边界保护、碰撞空间、受控接近和退让动作，以及实测验证；本阶段不发送运动指令。

## 原始坐标输出

请求：`POST /api/vision/analyze?square_mm=20`，请求体为 PNG/JPEG 字节流，`Content-Type: image/png` 或 `image/jpeg`。响应包括 `checkerboard.corners_px`、`ball.center_px`、`ball.board_grid_xy`、`ball.board_mm_xy`（仅在已提供实际L时）和 `warnings`。

为了避免误操作，服务端的视觉分析路径不引用机械臂实例、不接触串口、不执行运动指令。
