# 挑战升级：三色球逐个入碗

入口：`http://127.0.0.1:8765/challenge`，顶部独立的「挑战升级」tab。

三个球颜色不同，直径均为34mm；沿用当前收集容器、标定与相机服务，不增加尺寸填写项。原「抓取试验」继续用于单球RSI。

## 现场使用

1. 从此分支更新并重启网页服务，保持原 Python、串口、标定和公司模型配置。相机服务已有实时画面、RGB-D与录像请求ID能力时直接沿用。
2. 放好三个不同颜色的球及原收集容器，打开「挑战升级」。可先点「识别桌面（不运动）」核对快照、球数及XYZ。
3. 确认现场已清空后点「开始挑战」。未手动授权的`armed=false`不会阻止此入口；按钮点击的任务声明包含自动回位和逐球连续执行授权。
4. 程序选一个完整抓放路径可执行的球，复用main的高处运输路径、合抓、抬升、投放和20秒录像。录像结束先回官方姿态，再分析本轮，重新定位余下的球。
5. 第一个球成功不会终止。没抓住、滑落等可继续尝试，参数相同也可重试，没有五轮上限。三个球都有入碗证据，且连续两次新观察确认桌面清空时，显示绿色完成提示并自动结束。

「停止挑战」阻止后续指令、回位及重试，已接受的动作可能继续。页面加载、刷新、查看图片和读取状态不会启动动作。单球任务、坐标控制和挑战共享一个控制器，不能同时运行。

## 定位与学习

- OpenCV按颜色找球候选，RGB-D结合保存的桌面和17mm半径拟合球心。白球、黑球需深度前景证据，以区别桌面和容器。可靠深度不足时，只在同一次真实图像得到模型确认后使用保存桌面估计，明确标注来源。
- 直接调用当前配置的视觉API，发送实际JPEG图像（长边最多768px），不把本地路径当作图片。桌面识别报告球框、颜色、遮挡和容器内颜色；逐轮复核限定本轮选中的颜色，保留抓起后滑落与从未抓住的区别。
- 模型分析后再采新的RGB-D用于规划；旧球框不能充当新帧的目标。运动仍由原XYZ/IK、实际反馈及分段间隙检查执行，不让模型直接给运动指令。
- 经验参数首次从现有单球策略复制，之后独立保存，不改写单球经验。定性偏差仍由程序按已标定相机关系换算，不另加镜像硬翻转。
- 进碗确认来自本轮录像或新画面内的容器证据；球仅从桌面消失，不能算进碗。遮挡、未定位候选、不可达剩余球或执行/相机故障会保留原因，不显示清台成功。

## 本机数据和接口

- 任务、逐轮录像索引、定位快照、模型请求及回复：`~/.evoarm/rsi/challenge_sessions/<任务ID>/`
- 挑战经验：`~/.evoarm/rsi/challenge_policies/<setup_id>/<标定指纹>.json`
- RGB-D：沿用`~/.evoarm/rsi/experiments/<采集ID>/`
- 每轮完整ZIP：沿用`~/.evoarm/rsi/backups/<试次ID>.zip`
- Langfuse待同步：沿用`~/.evoarm/rsi/langfuse-outbox/<试次ID>.json`，包含挑战任务和目标颜色，不进行远程提交。

只读：`GET /api/challenge/state`、`/history`、`/events`；重新采集但不运动：`POST /api/challenge/observe {}`；开始：`POST /api/challenge/start {"declaration":"现场已清空，允许逐个抓球入碗、自动回位和连续尝试"}`；停止：`POST /api/challenge/stop {}`。

`challenge_api_version=1`。每轮资产位于`/api/challenge/sessions/<任务ID>/trials/<试次ID>/{video,keyframes,archive,state}`。

离线测试使用合成RGB-D、模拟控制器和模型回复，桌面浏览器验收拦截全部设备接口。三色球实物抓放仍需在本机验收。
