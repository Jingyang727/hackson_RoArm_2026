# 挑战升级：连续抓球入碗

入口：`http://127.0.0.1:8765/challenge`，顶部独立的「挑战升级」tab。

球的颜色不同，直径均为34mm；首次识别前桌面剩余留空，已确认入碗只显示数量，不固定分母，也不显示清空复核计数；沿用当前收集容器、标定与相机服务，不增加尺寸填写项。原「抓取试验」继续用于单球RSI。

## 现场使用

1. 从此分支更新并重启网页服务，保持原 Python、串口、标定和公司模型配置。相机服务也应更新并重启，继续使用原Gemini Python和原权限方式。新版health增加`recording_finish=true`，支持动作结束后停录；旧相机服务可继续运行，但仍等满20秒，页面会提示。
2. 放好不同颜色的球及原收集容器，打开「挑战升级」。可先点「识别桌面（不运动）」核对快照、球数及XYZ。
3. 确认现场已清空后点「开始挑战」。未手动授权的`armed=false`不会阻止此入口；按钮点击的任务声明包含连续抓放和故障时自动回位授权。
4. 程序选一个完整抓放路径可执行的球，复用main的高处运输路径、合抓、抬升、投放和实际反馈检查。正常轮次不恢复初始姿态，从投放后的实际位置接着规划。录像最多20秒；启用新相机能力后，动作结束再保留0.4秒投放画面即可停录。
5. 第一个球成功不会终止。没抓住、滑落等可继续尝试，参数相同也可重试，没有五轮上限。球数由当前识别动态确定，不要求凑够三个。桌面已无球时做一次模型画面确认，结束连续抓取；全部已确认入碗时显示绿色提示，去向未确认的球不增加入碗数。

「停止挑战」阻止后续指令、回位及重试，已接受的动作可能继续。页面加载、刷新、查看图片和读取状态不会启动动作。单球任务、坐标控制和挑战共享一个控制器，不能同时运行。

## 定位与学习

- OpenCV按颜色找球候选，RGB-D结合保存的桌面和17mm半径拟合球心。白球、黑球需深度前景证据，以区别桌面和容器。可靠深度不足时，保留未定位候选；模型确认颜色后只使用新帧中重新检测的轮廓与保存桌面估计，明确标注来源，不沿用模型旧框的位置。
- 每次开始挑战时，从新采集的RGB-D定位大漏斗口并锁定到本次任务；后续球的定位、入碗观察及空桌复核沿用这份口沿几何，不会因夹爪或已入碗球遮挡口沿而重新拟合失败。小球和入碗证据始终来自实际新画面。位置与采集来源保存在任务的`container_reference`及每份定位结果的`bowl_location`。移动漏斗后停止并重新开始挑战；新任务及单独的「识别桌面」均重新定位，不复用上次任务位置。相机画幅、内参或活动标定改变时原锁定失效。
- 正常非空场景先用本机RGB-D快速定位，复用本轮录像最后的RGB-D，避免每球重复等场景模型。只有空桌、缺少可靠定位或需要分析失败时，直接调用当前配置的视觉API，发送实际JPEG图像（长边最多768px），不把本地路径当作图片。桌面识别报告球框、颜色、遮挡和容器内颜色；逐轮复核限定本轮选中的颜色，保留抓起后滑落与从未抓住的区别。
- 模型分析后再采新的RGB-D用于规划；旧球框不能充当新帧的目标。运动仍由原XYZ/IK、实际反馈及分段间隙检查执行，不让模型直接给运动指令。
- 抓空、滑落等录像分析在后台运行，不阻塞下一次抓取；同一时刻最多一个录像模型请求，每种颜色只保留一个最新待分析样本，原始录像全部保留。后台旧参数的回复不能覆盖当前新策略。
- 经验参数首次从现有单球策略复制，仅挑战模式将转移速度初始化为1.0、下探速度0.6，保留原有更快设置，后续可按滑落结果下调。之后独立保存，不改写单球经验。定性偏差仍由程序按已标定相机关系换算，不另加镜像硬翻转。
- 进碗确认来自本轮录像或新画面内的容器证据；球仅从桌面消失，不能算进碗。遮挡、未定位候选、不可达剩余球或执行/相机故障会保留原因，不误计入碗成功；已无桌面球但去向未确认时显示独立说明。
- 真正的任务异常会在「挑战暂停」下方显示暂停原因与发生阶段，同时写入过程事件和任务`state.json`；暂停状态不会再显示「可以开始连续抓放」的就绪提示。
- 未被自动任务占用时，挑战页会持续只读采样，包括坐标页发起的官方回位或移动的到位确认。回位确认中显示等待时间和关节误差，完成后自动更新按钮；稳定但偏离目标、超时或串口错误按原反馈规则显示真实异常，不清空故障或重发动作。其他任务占用会显示任务ID，本次任务收尾会单独说明。页面状态请求不重叠，避免固件忙时积压反馈查询。

## 本机数据和接口

- 任务、逐轮录像索引、定位快照、模型请求及回复：`~/.evoarm/rsi/challenge_sessions/<任务ID>/`
- 挑战经验：`~/.evoarm/rsi/challenge_policies/<setup_id>/<标定指纹>.json`
- RGB-D：沿用`~/.evoarm/rsi/experiments/<采集ID>/`
- 每轮完整ZIP：沿用`~/.evoarm/rsi/backups/<试次ID>.zip`
- Langfuse待同步：沿用`~/.evoarm/rsi/langfuse-outbox/<试次ID>.json`，包含挑战任务和目标颜色，不进行远程提交。

只读：`GET /api/challenge/state`、`/history`、`/events`；重新采集但不运动：`POST /api/challenge/observe {}`；开始：`POST /api/challenge/start {"declaration":"现场已清空，允许连续抓球入碗及故障时自动回位"}`；停止：`POST /api/challenge/stop {}`。

`challenge_api_version=2`。每轮资产位于`/api/challenge/sessions/<任务ID>/trials/<试次ID>/{video,keyframes,archive,state}`。

离线测试使用合成RGB-D、模拟控制器和模型回复，桌面浏览器验收拦截全部设备接口。三色球实物抓放仍需在本机验收。

本次优化仅对挑战模式生效。相机与执行器的提前结束能力为显式可选参数；单球抓取页仍按原20秒录制、回位和分析流程执行。
