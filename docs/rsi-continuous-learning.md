# 连续尝试与相同参数重试

抓取页默认选择“持续尝试，成功或手动停止”。不再默认五轮，也不再限制最多二十轮；可以选择预设轮数，或输入任意可表示的正整数轮数。有限任务成功时提前结束，未成功时执行到所选轮数；持续任务没有轮数上限。手动停止、控制器故障、缺失反馈、不可达路径、采集或接口异常仍按原有流程停止后续动作。服务重启后不自动续跑。

每轮仍完整执行：重新RGB-D定位 → 重新规划 → 抓放及20秒录像 → 官方回位确认 → 视觉复核 → 保存结果与策略 → 下一轮。它是新的试次和请求ID，不是重发上一条未确认的运动指令。录像长度、模型图像长边768px、最多六张图片和既有几何检查均保持。

动作与录像已确认完成时，模型没有明确方向、返回unknown、未产生参数变化，或建议的新参数未通过完整路径检查，均可保留原参数继续重新定位与尝试。候选参数未通过路径检查时只保留原参数，不下发该候选。UI记录“本轮保留相同参数”，不会声称发生了参数学习或误差改善。

前后实帧否定某项修正时，仍撤销该项修正。回滚后的重复试次不会把“回滚本身”再次撤销；相同位置与姿态下，已被否定的方向不会仅因更换步长而重新应用。其他有证据支持的新修正仍可保存和试验。

执行未完成与没有视觉修正是两类情况：串口/反馈错误、采集错误或未启动的动作不能凭“允许相同参数重试”跳过处理；执行预算、实测抬升或投放间隙故障继续沿用已有诊断与参数试验规则。下一轮始终重新检查新鲜状态和完整路径。

## 接口与记录

`GET /api/bench/rsi/state` 返回 `continuous_learning_version=1`。`POST /api/bench/rsi/learning/start` 的 `max_attempts` 可为正整数，或null表示持续尝试；省略时也为null。`learning.continuous` 标识持续模式，`learning.attempt` 是当前轮数，`learning.trial_count` 是已复核的试次总数。前端发现旧后端时要求重启，不把null发送给不支持连续模式的旧服务。

完成动作的复核结果包含 `proposal.retry_mode=same_parameters|updated_parameters` 和 `retry_reason`；`allow_retry`不再仅取决于是否改参数。每轮录像、模型输入与输出、轨迹、参数和判断继续保存到原有目录及完整试次备份，Langfuse outbox保持。网页状态保留最近100条试次摘要，历史完整记录保留在磁盘；控制服务只缓存近期终态计划，历史查询从磁盘读取。

本改动解决“无明确修正就终止”和固定轮数上限。用户报告的“短暂夹起后滑落被误判为空抓”，仍需用该轮原始录像和实际模型输入确认抽帧或识别原因；本改动不把未经复核的滑落当作已正确识别。
