# 移动控制 checkpoint 与 RSI 接入约定

2026-11-13：用户确认 `f610420` 的XYZ移动与官方复位版本为重要checkpoint，要求合入main，后续在此基础上接RSI。合并快照通过 `checkpoint-xyz-control-v1` 标签定位；随后增加的左右镜像只影响坐标图显示和选点反投影。运动执行链不重写。

## 坐标与设备约定

- 设备为RoArm-M3-S原装夹爪和Gemini双目RGB-D相机。球直径34mm，漏斗开口内径76mm、高45.4mm，漏斗位置可变。
- XYZ使用机械臂固件基坐标系，单位mm；X向前、Y横向、Z向上，Z=0不是桌面。固件XYZ代表名义指尖，不等于张爪时的球心或夹持中心。
- 关节、俯仰、旋转、夹爪的固件反馈及T104工具角以rad表示。页面角度以度展示，不能把度数直接填入T104角度字段。
- 相机、机械臂底座、桌面默认固定，直到用户报告变化。沿用bench-layout-v2五点标定，棋盘可撤走；运行不要求重新检测棋盘。相机服务继续独立运行，机械臂串口仅由ArmService持有。
- UI左右镜像不改坐标符号、不改标定、不改命令、不触发动作。镜像视图选点仍回到同一个机器人XYZ。

## 当前HTTP接口

默认地址 `http://127.0.0.1:8765`，坐标页 `/coordinates`。`GET /api/coordinates/state` 的 `coordinate_api_version` 为5。

| 接口 | 用途与行为 |
|---|---|
| `GET /api/coordinates/state` | 新鲜T1051、六关节锁定状态、FK骨架、保存桌面平面、执行结果和官方范围；只读 |
| `POST /api/coordinates/prepare` | 纯计算XYZ和全路径，返回plan_id、180秒有效期、最终姿态与单次T104；不授权、不移动 |
| `POST /api/coordinates/move` | 使用plan_id和现场声明，再次校验实际起点、标定、六关节锁定与全路径；一次发送 |
| `POST /api/coordinates/verify` | 保存人工实物核对：matches、offset、uncertain；不发送运动 |
| `GET /api/home/preview?kind=factory` | 当前六角度→官方初始目标；只读 |
| `POST /api/coordinates/factory-reset` | request_id与明确现场确认；静止复核后发送一次T100，必要时先只读复核故障 |
| `GET /api/coordinates/depth-snapshot`、`POST /api/coordinates/depth-point` | 查看已有RGB-D录像、将有效表面深度变换到机器人坐标；非实时、不是自动球心、不会移动 |

XYZ准备载荷：

```json
{"xyz_mm":[300,20,50],"pitch_mode":"auto"}
```

`pitch_mode=auto`优先保持当前全局俯仰，必要时搜索其他可达俯仰；`hold`强制保持当前俯仰。预览文字和灰色骨架显示最终姿态。执行固定使用该计划，不在发送时重新搜索或自动换路径。

最终俯仰取`plan.command.t`或`plan.orientation.target_pitch_deg`；兼容字段`pose_preserved_rad.pitch`在auto模式下也表示目标值，不保证等于起点。

移动载荷：

```json
{
  "plan_id":"<prepare返回的32位编号>",
  "declaration":"已核对XYZ目标和路径，现场有人看护且双手离开运动范围"
}
```

此声明沿用当前现场确认语义。后续RSI运行会话的授权与循环应明确接入此执行边界，不另开串口，也不在模型分析阶段发送动作。更新目标或俯仰模式需要重新prepare；HTTP响应不确定时查询状态，不直接重发move。

plan_id只在当前网页服务实例中有效，服务重启后需要重新prepare。已经位于目标附近时返回`sent=false`、`already_at_target`，没有额外发送动作；这与抓取结果无关。

官方复位载荷：

```json
{
  "request_id":"<每次确认独立生成的32位小写十六进制编号>",
  "declaration":"已确认机械臂静止、阻挡已解除、整臂回位空间已清空且双手离开运动范围"
}
```

复位只作为人工确认的恢复入口，不用于自动脱困、急停或每轮RSI的必经动作。有pending时禁止叠加。T100本身执行官方肩部对齐、全臂回位和闭爪；软件不额外发送扭矩切换。请求ID在发送前持久化，同一ID即使服务重启也不重放。

## 固件运动原语

XYZ计划发送以下形状的T104；实际数值来自prepare，示例不是可直接执行的现场计划：

```json
{"T":104,"x":300,"y":20,"z":50,"t":0.7,"r":0,"g":3.14,"spd":0.12}
```

- `t`是全局末端俯仰，不是腕关节角。`r`为末端旋转，`g`为夹爪角；XYZ验证保持旋转与合法夹爪开度。
- 反馈使用T105请求、T1051响应；关节字段为b/s/e/t/r/g，工具俯仰字段为tit，扭矩位为torswitchB/S/E/T/R/G。
- 六项1或true才确认锁定；0可能是释放或舵机反馈读取失败，不能单凭该位断定物理释放。负载tR=0不代表扭矩关闭。
- 抓放的开合原语是T106，cmd为rad，文档范围1.08～3.14；速度单位是舵机步/秒，与T104的spd含义不同。当前坐标移动不会附加开合动作。
- 官方复位仅发送 `{"T":100}`，名义目标为0°、0°、90°、0°、0°、180°，反馈到位与实物准确度分别判断。

## 必须沿用的执行行为

`evoarm/limits.py`是范围的唯一数值来源：底座/旋转±180°，肩/腕±90°，肘0～180°，夹爪按官方rad边界处理。不恢复旧±75°/±50°/35～145°/±60°/±90°训练限制、固定25mm末端高度门槛、选点网格截断或先收腕55°的旧流程。

保留保存桌面、全路径IK、官方角度范围、底座分支连续性、起点/标定一致性及上游连杆30mm项目间隙检查。末端目标最低到保存桌面0mm；这不等于有完整实物防碰撞能力。真实发送需要新鲜锁定、无待完成动作和有效现场授权。

计划在写串口前消耗；双击、刷新、错误响应和不确定写入不自动重放。控制反馈稳定但有偏差要如实记录，不要求夹爪角完全一致才确认XYZ，也不把HTTP成功或数值到位当作抓取成功。

XYZ证据在 `~/.evoarm/rsi/coordinate_runs/<plan_id>/report.json`；复位防重放请求在 `~/.evoarm/rsi/factory_resets/<request_id>.json`，其中sent_not_verified仅表示发送，最终结果以反馈为准。标定、相机录像与这些本地数据不提交到仓库。

## 下一阶段RSI

复用上述移动原语，把人工选XYZ逐步替换为黄色球RGB-D定位。先用桌面、34mm球径与有效球面深度确定大概抓取位置，动作顺序为到上方、张爪、下降、合抓、提升、移至当前漏斗上方、释放。

Grok负责定性结果：抓住与否、偏左/右/前/后、投放是否成功等；不假定它能给出可靠毫米误差。程序依据这些类别和执行记录，对最后几步的下降高度、偏移、开合与时序参数作有界调整，再生成下一轮计划。自动循环与漏斗投放仍待实现，当前checkpoint不宣称它们已经完成。

完整抓放以10秒为目标，录像覆盖动作并保留RGB-D和轨迹。录像长度、实际动作耗时和任务成功分别记录。Langfuse可做记录与检索，但记录不会自动进入Agent上下文，需显式读取历史并提供给Grok。公司Grok/OpenCode在本地执行，云端不直接控制机械臂。
