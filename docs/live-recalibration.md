# 相机或机械臂底座移动后的重新标定

打开 `/calibration`，顶部“读取当前棋盘”现在始终显示。可以先点“开启实时画面”，在还没有标定参考时看当前相机原图；再点“采集当前棋盘并重新标定”。不需要事先录制空棋盘视频或选择旧录像。

保持相机、底座和棋盘固定，让全部9×6、54个内角点可见，填写本轮实测的单格边长；用户最新重新实测确认为24.92mm。按钮通过现有独立相机服务采集2秒当前RGB-D，检查至少3帧完整且稳定的角点，生成显示全部角点和P1–P4、V1的参考图。此步骤不连接或移动机械臂，不切换扭矩，也不依赖Grok。

检测成功后进度从0/5开始。按原流程支撑、释放六关节，用同一固定触点手动对准五点并记录；五点完成后恢复扭矩。实时画面叠加本次参考的五点位置；进入人工对准后不再逐帧重排角点，以免遮挡时标记跳动。

每次重新标定建立独立目录：

```text
~/.evoarm/rsi/calibrations/<setup_id>/revisions/<新版本ID>/session.json
```

原来的 `session.json`、参考图、原始采点和试次都保留。`active-session.json` 保存当前版本指针，重启后继续当前版本，无需修改 `EVOARM_SETUP_ID`。浏览器标定、坐标验证、RSI和起步CLI共同读取该指针；新会话指纹会隔离旧RSI补偿。

按钮表示设备已经移动并要开始新标定，因此先切换到新版本，再采集。相机断开、角点不全或检测失败时保留“待重新标定”，不会回退旧布局继续抓放。调整画面后重新点击即可。五点记录齐全并通过拟合前，现有规划检查不会使用旧平面。已有运动或自动任务执行期间不能切换标定版本；页面加载、预览和采集按钮都不会代发释放、复位或抓放。

本地更新时沿用原Gemini Python和独立相机服务，只重启普通用户8765网页服务。`/api/bench/status` 的 `bench_api_version=3` 表示已加载实时重新标定与误差诊断更新。先验收实时预览、角点检测和新进度，再进行人工五点采集。

## 显示未通过时核对什么

结果页显示每项验收结果、五点记录与预测XYZ之差、沿棋盘列/行的分量、离平面高度，以及优先复核点。V1不参与拟合：只重采V1时，四点RMS按设计不变；独立验证误差会按新V1重算。现有验收阈值仍是RMS≤6mm、拟合点最大≤9mm、独立验证≤10mm，不改变运动范围，也不自动放宽。

点位同时显示人用行列数：从左上第一个内部角点开始数，V1为第3行、第5列（零起点格点4,2）。选择建议复核点只改变标记，不移动机械臂。记录−预测的差值用于排查，不能直接当成运动指令；当前拟合通过也不证明每个触点都正确。

本轮读取V1棋盘坐标 `[99.68,49.84]`，确实按24.92mm计算。当前矩阵预测V1约 `(354.449,8.275,-119.075)`；实际记录 `(380.945,5.844,-117.004)`，沿棋盘列/行约差 `(-2.995,+26.510)`mm，离平面约+0.699mm，独立误差26.688mm。它更像多了一行，仍需核对原图标记和实际触点；不能单凭数值断言操作者触错。用同一四点拟合回算上一份V1约25.356mm，证明“显示相近”不能直接当成“采点没更新”。

每次采点保存唯一capture_id、时间、三次查询、旧/新XYZ与差值、旧验证误差及累计采点版本。完全相同的反馈会明确标出，不能用新时间戳冒充实物已改变。历史点与原始样本继续保留。拟合结果绑定输入采点版本，重采接口绑定所见会话并始终在同一路径拟合，防止旧标签页误写新会话。旧会话的诊断可只读重算显示，无需再触碰五点。

刷新页面会回填实际保存的单格尺寸；修改输入框是下一次“采集当前棋盘”的参数，不静默修改已有参考或五点。页面明确显示当前已采用值及未提交变化，避免输入框默认值与保存数据不一致。
