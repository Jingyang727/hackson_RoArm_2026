# 合爪后抬升起点误拦修复

用户试次 `e74cebc16a87491db61b67ccdd953540`（运行提交 `61f79d1`）在 `lift` 的路径0%报指尖低于0mm。提供的合爪反馈XYZ为 `[386.8582738,-2.967223983,-118.5901445]`，俯仰1.322291439rad；按该轮倾斜桌面计算，实际反馈点离平面 **−0.684667528mm**。这触发了通用路径检查，抬升指令尚未发出，运输和投放也未执行。之后的既有故障回位分支会先在当前位置张爪，再执行T100，因此球不会被送到漏斗。

## 与 main 的核对

对照 main `e3eaf65`（文件内容对应 `1fb707b`）：动作发送器、球/漏斗识别、录像窗口和投放间隙原先相同；缺陷所涉及的抬升起点判定在main同样存在。此前本分支修改了按所选投放姿态计算运输高度，没有删除任何抓放阶段。对同一份历史归档、同一输入和参数回放，main与分支均含合爪、抬升、运输、投放，抓取和最终投放点相同；该历史例的中转高度从169.642mm变为156.220mm。这个高度差不改变起点0mm门槛，不能解释本次0%拒绝。之后按用户要求恢复main的统一高处通道；路线版本7在该历史例中恢复到169.642mm，起点修复继续保留。

## 修复行为

`execution_target` 对 `raise_current` 和抓后 `lift` 显式处理离桌起步：保持实际反馈XY，目标Z只能向上，终点必须回到桌面及本段原有要求以上。若起点低于本段门槛，本段路径的最低点为实际起点，整条竖直线不能继续下探。原有IK、关节范围、上游连杆间隙和后续运输/下探检查保持。

该轮实测数据已作为回归样本保存；源码重建IK测试中的末端旋转设为0rad，并在样本中明确标记，因为用户回传未提供该字段。几何回放复现旧检查的原始0%异常，修复后同一竖直抬升通过。另有完整模拟执行，在合爪后注入同样的负高度反馈，确认实际依次发送抬升、运输和释放指令，保留20秒录像及指令审计；不代表已做实机验收。

`stage-*.json` 的 `table_departure` 和日志事件 `upward_table_departure` 记录实际起点高度、目标高度及本段门槛。`GET /api/bench/rsi/state` 返回 `lift_departure_version=1`，更新代码并重启网页服务后可用于核对运行版本。
