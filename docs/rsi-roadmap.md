# EvoArm · 2026 黑客松：RSI（Recursive Self-Improvement）路线与验收

> 当前目标：**工作区内任意可达位置的黄色球 → 机械臂抓取 → 放到指定点**。
> 未来挑战：视觉追踪飞行球 → 预测落点/接球位置 → **接住空中软球**。
> 不将“模型会聊天/生成代码”当成 RSI。这里的 RSI 是**执行 → 可观测评测 → 定位失败原因 → 小幅参数修正 → 受控重测 → 优于旧版才替换**。

## 可落地的系统结构

```text
1080p 摄像头 (Mac WebRTC / 后续 Jetson)
      │ 多帧检测、相机畸变校正、棋盘/球/夹爪定位
      ▼
Perception  ──► World State (球中心/半径/置信度/静止/障碍物)
                        │
                        ▼
 Robot-XY 平面标定 + 工具 TCP + Z/球体高度模型
                        │
                        ▼
Planner (安全轨迹：接近、张开、下探、夹取、抬升、转运、放置、撤离)
                        │
                        ▼
Safety gate ─► Execution(T=104/T=106) ─► T=1051反馈
                        │                      │
                        ▼                      ▼
  多模态评测 (球是否消失/夹爪是否夹住/放置区是否出现球 + XYZ/角度/时延)
                        │
                        ▼
  Trial Store (帧、定位、标定版本、动作、真实反馈、成败、失败标签)
                        │
                        ▼
  RSI Optimizer (只提议受控的小幅参数修正，离线重放 + 真机灰度验证)
                        │
            approve / rollback / promote
                        ▼
          next safe policy version
```

## Stage 0：连接和标定基座（正在做）

- Mac FastAPI 服务单一串口所有权，控制台/标定页共享状态，避免重复打开串口使 ESP32 初始化。
- 俯视相机支持 1080p 原始采集，9×6 棋盘内部角点识别。
- XY：4 个拟合点 + 1 个独立验证点；保存相机/棋盘54角点指纹，检测被移动后拒绝动作规划。
- 工具姿态：必须使用反馈中的 `tit` (末端 Pitch)，不能误用 `t` (腕关节角)。
- 安全：运动使能、扭矩示教、故障恢复、真实执行授权分别隔离；掉线或不确定反馈时停止下发**新指令**。

## Stage 1：抓放闭环（先让任务可重复）

当前已有：`/calibration`、`/pick`、轨迹预览、默认关闭的人工逐段T=104/T=106执行框架。

接下来**必须实机完成的校验**：

1. **TCP**：用相同姿态/高度的夹爪中心对齐纸面目标；把机器人 T=1051 的末端参考点和两指中心的物理偏移单独记录，不混用。
2. **球体高度/视差**：俯视图中颜色质心高于桌面，不能直接套桌面单应矩阵就当作接触点；在不少于 5 个已知桌面位置上统计视觉落点偏差，修正镜头畸变和球高相关误差。
3. **抓取**：实测球直径、夹爪有效开/闭角、抓取 Z，先低速试夹同一个固定位置并检查抬升后球仍在夹爪中。
4. **放置**：固定目标点，记录放置 XY+Z、撤离高度和允许触碰区域。
5. **执行**：每条动作均需确认真实XYZ/关节反馈；硬件不支持通过软件按钮完成可靠急停，需要独立断电方案。先 1 次受控人工步骤序列，再做 3 个位置轮换复测。
6. **验收**：至少在已标定的安全凸包区域内选择 5 个不同起点，每点尝试 3 次，记录 `success_pick`、`success_place`、绝对落点偏差和异常次数。目标可迭代设为 ≥80%/15 次的成功率；这不是目前实测结果。

**暂不承诺“摄像头整个画面任意位置”**：只有符合机械臂运动学、夹爪尺寸、平面标定和障碍物约束的区域才算合格工作区。

## Stage 2：RSI v1 —— 小规模在线自我修正

先做不需要训练大模型的**残差校正**，更适合机器人黑客松现场证明价值。

参数版本：
- `xy_offset_mm=(dx,dy)`: 视觉球心/夹爪实际落点偏差修正；
- `z_pick_offset_mm`: 抓球高度修正；
- `g_close_rad`: 闭合角修正；
- `z_safe_mm`: 经验证的抬升安全高度；
- 每个参数有限界（例如XY单次提议≤3mm、Z单次提议≤2mm），边界按真机实测收紧，超限不执行。

每次 trial 保存（本地 SQLite/Parquet，文件放 `~/.evoarm/trials/`，**不要上传包含家庭/工厂画面的完整视频到云端**）：
```json
{
  "trial_id":"uuid",
  "calibration_version":"sha256...",
  "policy_version":"v1",
  "ball_board_xy_mm":[96.0,60.0],
  "predicted_robot_xyz_mm":[250.0,-21.0,110.0],
  "executed_steps":[],
  "feedback_xyz_mm":[],
  "ball_detected_after_lift":true,
  "ball_detected_at_place":true,
  "pick_success":true,
  "place_success":true,
  "placement_error_mm":4.2,
  "failure_type":null
}
```

Evaluator 可结合俯视视觉和人工确认。优先采集：静态空桌、球在起点、夹住抬升、放置结束四帧 + 真实机器人反馈；无需全程录制。

Optimizer:
1. 对失败 trial 分类：`detect_miss`、`XY_offset`、`Z_contact`、`grip_slip`、`motion_stall`、`drop`、`place_miss`。
2. **只在无硬件故障/碰撞的失败上生成修正候选**，使用坐标残差均值/稳健中位数或小尺度黑盒搜索，不依靠 LLM 臆测姿态。
3. 在离线历史 trial 上重算预测并执行安全约束校验；只有修正幅度小、历史误差下降才提交“候选策略”。
4. 单次低风险灰度验证由操作员显式批准；通过后版本升级，任何失败可一键回滚到上一已验证参数。
5. 采样 5～15 组即可做第一次可见改进（不保证最优，但能演示闭环），与基线在同一组目标点比较。

**RSI 的演示**：展示第一轮重复抓取偏左/偏低 → evaluator 定位为定量误差 → optimizer 给出补偿建议 → 通过护栏后再试 → 观察成功率/落点误差提升。必须对照同样环境，不用靠“自称优化成功”。

## Stage 3：空中接球（第二项目阶段）

使用软球/接球杯替代硬球两指夹爪，先做**落点接住**，不是一开始就追逐球的瞬时位置。

- 摄像头从俯视固定视角升级为**能看见飞行轨迹深度的双相机或RGB-D/侧视视角**；纯俯视 2D 无法唯一恢复飞行球的三维轨迹与高度。
- 追踪时刻 `t, (x,y,z)`，拟合带重力的短时弹道；每帧预测交会位置和时间，计算预测不确定性区间。
- 实测“视觉采集→检测→预测→串口→关节动作→到位”的延迟，判断能否在球落地前完成到位。1080p/30fps单帧理论间隔≈33ms，但**USB相机总延迟、串口及T=104动作时间远大于单帧间隔且必须实测**。
- 如果 RoArm-M3 实测无法从任意姿态及时移动，就采用**预定位杯口、局部小范围修正、固定投球区域**，不承诺高速空中追踪和拦截。
- 先验证静止杯口接住抛落软球，再允许低速小范围预测位移；之后再探索移动接球。

## 明确的安全边界

- RSI 优化器**不能修改安全门槛、自动复位/恢复扭矩或自动解锁真实机械臂**。
- 完整自动试错需先有成熟的可达性检测、碰撞/接触护栏、独立停止手段、模拟环境和已验收的动态范围。
- 指令 `T=1041` 无底层插值，不能用于大跨距突变；优先 `T=104` 分段慢速并验收状态。官方 `T=105` 是只读；`T=210` 扭矩释放不是紧急停止。
- 每个策略版本与标定版本强绑定，标定/相机姿态变化后策略失效并要求重新验证。
- 如果发生机械臂自发下沉、供电异常、碰撞或无法确认状态，先停止验证并处理硬件，不把问题交给 RSI 自我修正。
