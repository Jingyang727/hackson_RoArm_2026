# EvoArm — RoArm-M3 中文控制台 v0.4.2

Mac M1 + USB 串口 + RoArm-M3-S / Pro：六关节手动步进、XYZ/角度反馈、俯视相机预览和自定义复位姿态。

**此前已发生机械臂碰撞显示器事故。** 启动运动功能前必须检查夹爪、关节、固定装置与供电，移除机械臂扫掠范围内的显示器、人员和易损物品，并保持能够立即切断动力电源。软件限位和网页“锁定新动作”并非硬件急停。

## Mac 安装

```bash
git fetch origin
git switch --track origin/fix/evoarm-motion-pending-v0-4-2
# 若本地已有此分支：git switch fix/evoarm-motion-pending-v0-4-2 && git pull --ff-only
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

### 只读启动（默认）

```bash
python -m uvicorn control_ui.main:app --host 127.0.0.1 --port 8765
```

浏览器：`http://127.0.0.1:8765`。摄像头预览：`http://127.0.0.1:8765/camera`。

### 手动控制启动（务必先完成现场物理检查）

停止旧服务，然后：

```bash
EVOARM_ENABLE_MOTION=1 EVOARM_ALLOWED_JOINTS=1,2,3,4,5,6 \
python -m uvicorn control_ui.main:app --host 127.0.0.1 --port 8765
```

网页连接机械臂后，点击“确认安全并解锁”，在120秒内可发送多次**独立、有限距离**的单关节步进。1° / 3° / 5° / 10°可选（默认5°）。关节手动步进不再每次弹窗确认；一次解锁120秒有效。不允许长按连续转动，不允许同时发送两个运动指令；后端需得到上次动作到位反馈后才允许下一步。若无法确认反馈，后续动作会拒绝，需排查而非绕过。

- `T=1051` 状态关节角度以弧度上报；`T=121` 的目标角度以度发送；
- 后端速度限制 15°/s、加速度 20°/s²；
- 训练范围（非防碰撞边界）：底座±75°、肩部±50°、肘部35°～145°、手腕俯仰±60°、末端旋转±90°、夹爪65°～180°；
- 动作启动之前会检查关节扭矩状态，异常则拒绝；
- 软件停止仅**禁止新的指令**，不能保证停止已经发送到固件的动作；
- 若不希望一次开放所有关节，可只设置 `EVOARM_ALLOWED_JOINTS=6`，先从夹爪测试开始。

## “复位”说明

微雪提供 `{"T":100}` 官方初始化指令，会触发整条机械臂回初始姿态。现在在手动模式下可以选择 **“恢复官方初始姿态（T=100）”**，它会直接发送固件官方复位指令，让多个关节同时运动。此操作需要全六关节授权、主动解锁和单独危险动作确认。**执行前必须清空机械臂全部扫掠空间，官方复位没有软件避障能力。**

1. 在确认安全后，通过手动控制把机械臂调整到合适的实验待机姿态。
2. 点击“保存当前位置为我的复位点”，将六关节反馈角度记录在 Mac 本地 `~/.evoarm/home_pose.json`。
3. 选择“我的安全复位点”或“官方初始姿态”，查看各关节当前角度、目标角度和差值。
4. 点击某个关节的“回位一步 ≤5°”；每次只执行一个有限步进，等待确认到位后再执行下一步。

**官方复位**现在有单独按钮（T=100，六关节同时运动）；**自定义复位**仍使用每次最多5°的手动分段回位。两者都不能保证无碰撞。

## 夹爪控制和边界恢复

- 夹爪专用按钮通过官方 `T=106` 实现：**张开**（角度减小）、**夹紧**（角度增大），步长5°、15°、30°。
- 用户反馈过当前角度例如 **180.9°**，但原有软件边界为65°～180°，因此老版本所有夹爪动作都被拒绝。修复后允许在边界外2°容差内 **只向安全区间内移动**：180.9°可以张开5°/15°，不允许再夹紧。
- 角度反馈超过182°或低于63°时，软件拒绝继续驱动夹爪并提示人工检查，不会自动复位。
- 发送指令仅代表下发，不代表机械臂确实夹紧或张开；必须观察实际机械动作和关节反馈，若反馈不变化，请停止测试并提供错误消息及原始T=1051状态。
- 手动关节和夹爪每次点击不再重复弹出确认，但启动运动仍需一次解锁；官方 T=100 复位仍须独立危险动作确认。

## 相机高度调整

`/camera` 页面本地预览 USB 摄像头。相机调整高度后重新固定并截图，后续基于棋盘格建立桌面平面坐标。**每次修改相机高度、姿态或位置都需要重新标定。** 本版本未开启视觉自动抓取，也不会上传相机画面到云端模型。

## v0.4.2 修复：调整几次后长时间无法继续移动

**现象**：连续调整几个角度后，「增加/减少」按钮变灰、没有反应，长时间没有提示。

**根因**：旧版在发送 `T=121` / `T=106` 后，只要传感器反馈与目标角度相差超过 2°，就永远保留 `pending`（等待到位）标记。UI 因此永久禁用运动按钮。此外，普通串口状态读取单次可能等待20秒。

**现在的处理**：
- UI 直接显示正在执行的关节、目标角度、反馈角度、等待秒数。
- 普通串口状态读取超时降为4秒（首次 ESP32 连接仍给最多20秒启动查询）。
- 正常手动关节等待反馈最长10秒，夹爪最长12秒，官方多关节复位最长45秒。
- 如目标在窗口内到达±2°，自动释放 `pending`，下一条命令可继续发送。
- 若反馈未到达或串口读取失败，不会假装完成：界面显示故障详情，并锁定新的动作。请目视检查机械臂是否静止、关节是否有阻挡、是否供电正常。
- 「已检查机械臂静止 · 复核并恢复控制」按钮只检查两次连续且稳定的 `T=1051` 关节反馈（中间相隔0.75秒），**不会发送机械臂运动指令**。复核通过后仍需重新点击「确认安全并解锁」。
- 该故障流程与正常的运动授权120秒倒计时是两回事；UI 会分别显示。

**注意**：若舵机实际未到位或被桌面/物体阻挡，不能简单地自动清除异常、继续施加动作。软件角度判定不是力/碰撞检测；强制反复运动可能损坏机构。现场仍须保留电源级停机手段。

### 本地验收

```bash
python -m unittest discover -s tests -v
```

先在无障碍区域选择一个低幅度的单关节调整（例如5°），观察「动作执行状态」显示目标/反馈；连续调整三次确认成功。请勿为消除软件锁定而掰动已上电并锁扭矩的机械臂。
